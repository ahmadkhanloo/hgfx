## Research question and hypotheses

Can HGFX 1.0.0 and frozen MATLAB HGF Toolbox 8.2.0 evaluate the **same** likelihood and joint objective at identical transformed free-parameter vectors? If so, do their *different fitted endpoints* yield equivalent objective values even when optimizer trajectories differ? Distinguish `OBJECTIVE_IMPLEMENTATION_MISMATCH` from `OPTIMIZER_NUMERICAL_PATH_MISMATCH`, model-selection differences, and insufficient MATLAB/reference evidence. Objective agreement **alone cannot** be labeled scientific inferential equivalence or proof of identifiability.

Two panels are distinct:
- **Panel G (prior vector grid)**: three **binary perceptual** families with **`unitsq_sgm`** observations. Exactly **200** precommitted transformed-parameter vectors **per family**, giving **600** paired objective evaluations per implementation, irrespective of numeric status (successes and failures both retained).
- **Panel E (cross-endpoints)**: exact original **D02** (`ehgf_binary + unitsq_sgm`), **D08** (`uhgf + gaussian_obs`, *not* the binary uHGF model), and each of the **64 original full-fit `hgf_binary + unitsq_sgm` subjects**. At each original MATLAB endpoint and HGFX endpoint, evaluate the exact same vector in both implementations. Missing endpoints are accounted for explicitly and never replaced.

## Same-vector objectives, gradients and original unchanged gates

For **every fixed vector on both sides**, log:
1. transformed full vector and free indices hash, perceptual/observation config identity, trial input/response hash, `rval`/stability and error message, all nonfinite values, trial log-likelihoods and irregular mask when exposed;
2. `neg_log_likelihood`, Gaussian prior contributions and `neg_log_joint` (not fit endpoints alone);
3. first divergent **trial, level, state and intermediate variable**, or a precise `NOT_EXPORTED` marker when full numerical intermediates are absent;
4. gradient **only where both systems expose comparable gradients computed at the same vector**, with the method and h/epsilon fixed in advance and original comparator policy; otherwise `NOT_AVAILABLE` and no gradient PASS.

**Tolerances MUST NOT BE INVENTED OR RELAXED:** for the exact frozen M8 `hgf_binary + unitsq_sgm` objective path use `rtol=2e-11`, `atol=2e-13` from `tools/check_m8_parity.py`, applied elementwise with `abs(HGFX-MATLAB) <= atol+rtol*abs(MATLAB)`. For pre-existing M18 official fit/cohort comparison quantities, retain their original fieldwise frozen criteria (including `rtol=3e-8`, `atol=3e-10` for the subject-7 trajectories), never substitute this for an objective gate. For eHGF/uHGF fixed-vector objectives, locate and pin an **existing** family-specific registered objective tolerance before classifying any PASS; if none exists, report raw pointwise discrepancies and `NO_PREDECLARED_FAMILY_OBJECTIVE_GATE`, not extrapolated M8/HGF acceptance. **NaN-vs-NaN or `Inf`-vs-`Inf` is classified by finite-state status, not silently counted as a numeric PASS.**

The MATLAB reference may return a finite `realmax` sentinel for a failed perceptual evaluation; compare failure/status classification first. Report a value as a successful same-vector parity test only when both evaluations are valid and numerical fields are comparable. Nonfinite, missing and error rows remain in denominators, independent from both-finite pass counts.

## Input encoding clarification — recorded before any genuine objective experiment (2026-11-10)

The released binary-HGF configuration contains **intentional undefined/fixed `NaN` entries** in its full transformed parameter/prior vectors. The preregistered model family, 200 draws per family, fixed seed, transformed free-index ordering, 128-trial data, MATLAB oracle, objective and frozen tolerances are **unchanged**. To serialize the **same** mathematical full vectors as strict RFC-8259 JSON (`allow_nan=False`), `NaN` in undefined fixed slots is encoded as the literal string `"NaN"`, then decoded back to IEEE754 quiet NaN before evaluation; no substitution, finite imputation, rejection or new sample is allowed. Free parameter values must always be finite; infinities are not silently accepted. Full means, full transformed draws and prior-variance arrays use the same scalar encoding. The existing helper `validate_manifest` must verify NaN equality in fixed slots and all unchanged case SHA-256 values.

This amendment addresses **only transport/encoding of pre-existing undefined values**, documented prospectively after identifying a generator bug and **before any actual 1.0.0 MATLAB/HGFX paired experiment**. The earlier generator bug and its correction remain traceable in Git history. Re-review any MATLAB parser for strict exact input decoding before running the grid; this clarification is not permission to modify scientific inputs, model defaults, parameter masks or frozen numerical thresholds.
