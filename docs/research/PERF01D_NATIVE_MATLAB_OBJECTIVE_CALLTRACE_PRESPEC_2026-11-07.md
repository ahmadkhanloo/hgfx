## Source-based observation and exact boundaries

The wrapper calls `obj(x)` *exactly once per observed evaluation*, returning its **unaltered scalar value**. Every call is counted. Source MATLAB `dbstack('-completenames')` is inspected **after** the true private objective returns: a call is classified as optimizer-**direct** only if the immediate parent stack frame is the **frozen source `quasinewton_optim.m`** at a verified source-line containing the initial `val = f(x);`, trial `newval = f(newx);`, or reset `val = f(x);`. All calls indirectly made through `riddersgradient` / `riddersdiff` are counted but not classed as direct line searches. Source-line derivation must check the **unique** frozen `newval = f(newx)` line and the **two** source `val = f(x)` lines, rather than handcode line numbers that could point to the wrong statement. Unexpected direct callsites or stack identity are **not silently discarded**.

Archive each direct observation in original chronological order: call ordinal, MATLAB file/line, label (INITIAL / LINESEARCH / RESET / UNRECOGNIZED), exact binary64 free-coordinate vector and scalar source return, finite/sentinel status. Archive all non-direct count, first/last known source/native history records and full native/instrumented history arrays as provided, explicit original scientific 63/64 NONPASS, source/path/protocol/run identifiers, and full raw member SHA-256. This is a **call trace**, not instrumented source-level `if`/branch-event telemetry; interpreting that the optimizer *accepted* a trial requires checking exact original MATLAB `optim.iter` (including overwrite/NaN padded terminal slots). Inferences for ambiguous terminal records must explicitly remain **AMBIGUOUS**, never retrospectively relabel them accepted.
