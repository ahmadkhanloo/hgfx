## هدف و اولویت

محصول نهایی یک تولباکس مستقل پایتون است که رفتار علمی و عددی تولباکس ثابت MATLAB را در محدوده‌های مستند، با float64 و تلرانس توجیه‌شده بازتولید کند. وابستگی MATLAB فقط برای تولید مرجع توسعه مجاز است؛ اجرای روزمره پایتون به MATLAB وابسته نیست. پوشش کامل خانواده‌های علمی تعهد پروژه باقی می‌ماند؛ GPU و مقاله پس از اثبات صحت مسیرهای مربوط قرار می‌گیرند.

این سند ترتیب فعال کار را تعیین می‌کند. `MILESTONES.md` مرجع شماره‌گذاری است. بخش‌های فازی قدیمی `EXECUTION_PLAN.md` شرح معماری و سابقه طراحی‌اند و جایگزین ترتیب اصلاح حاضر نیستند.

## سه نتیجه مستقل

1. **تطابق پیاده‌سازی:** روی ورودی و تنظیمات یکسان، خروجی MATLAB و Python در محدوده خطای از پیش تعیین‌شده برابر است.
2. **بازیابی علمی:** آزمایش مشخص می‌تواند پارامتر یا مدل مولد را بازیابی کند. ضعف مشترک هر دو تولباکس ممکن است محدودیت مدل/داده باشد.
3. **اعتبار شواهد:** گزارش کامل، قابل بازتولید و متصل به کد و داده است. PASS این مورد جای دو مورد دیگر را نمی‌گیرد.

## ترتیب اجرا و گیت‌های کوچک

- کد اصلاح‌شده، SHA مرجع، محیط و هش M18 تاریخی را ثبت و کنترل کن.
- تست‌های `tests/unit/test_m18b*.py`، reference guard و regression را اجرا کن.
- `scripts/run_m18b_identifiability_validation.py --preset gate` را روی شبکه ثابت فعلی اجرا کن: 27 dataset و 81 parameter record؛ گروه‌های summary جای raw record را نمی‌گیرند.
- خروجی کامل، failureها، CI run/artifact ID، SHA256 و commit دقیق را آرشیو کن. اجراهای ناقص، smoke و GPU skip معادل PASS نیستند.

خروج: گیت معتبر با raw evidence کامل؛ اگر FAIL شد، علت همان گام رفع شود. پایان R0 صرفاً تعمیر شواهد M18B است.

### R1 — بازتولید زوجی شکست 512 تریالی

وضعیت: OPEN؛ Matrix IDs: P02/P03/P04، C01/C04، O17.

- از تاریخچه کد و log/artifact اجرای شکست‌خورده، seed، مولد ورودی، پارامترهای مولد، ماسک‌ها و تنظیمات را بازیابی کن؛ seed حدس زده نشود.
- ابتدا معلوم کن شکست در تولید داده، forward با truth، ارزیابی شروع fit یا probe مشتق رخ داده است. گزارش‌های فعلی برای تعیین قطعی محل کافی نیستند.
- داده و driverهای تصادفی را یک بار ذخیره و در هر دو زبان عیناً مصرف کن؛ seed یکسان به معنای RNG یکسان نیست.
- در MATLAB ثابت و Python CPU x64، config/transform/prior، مسیرهای `mu/sa/muhat/sahat`، خطاهای پیش‌بینی، likelihood و objective را مقایسه کن.
- اولین trial، level، field و متغیر میانی متفاوت را همراه مقدار و خطا ثبت کن. در مسیر نامتناهی، اولین محل غیرمتناهی و دسته خطا را گزارش کن.

خروج: fixture بازتولیدپذیر، خروجی MATLAB با metadata و گزارش اولین اختلاف؛ بدون دسترسی MATLAB، exporter و repro آماده شود و گیت صریحاً BLOCKED بماند.

### R2 — تصمیم و اصلاح بر مبنای مرجع

وضعیت: BLOCKED_BY_R1.

| نتیجه مقایسه | اقدام | شرط اتمام |
|---|---|---|
| MATLAB معتبر و Python متفاوت/نامعتبر | تست شکست‌خورده مرجع؛ اصلاح همان equation/branch/transform یا derivative | مورد شکست PASS و regression مسیرهای وابسته سبز |
| هر دو در همان رژیم نامعتبر | ثبت محدودیت مرجع و رفتار خطای سازگار؛ بررسی دامنه ورودی | محدودیت مستند و failure parity؛ هیچ ادعای پایداری در آن رژیم |
| هر دو معتبر و برابر | بررسی harness، محیط و provenance شکست تاریخی | علت مستند و اجرای بازتولیدپذیر |
| هر دو نامعتبر ولی اولین حالت‌ها متفاوت | بازگشت به اولین اختلاف | شکست مشترک مجوز صرف‌نظر از mismatch نیست |

clipping، تغییر prior، حذف seed ناموفق، کوچک‌کردن شبکه و افزایش تلرانس برای PASS ممنوع است. هر بهبود فراتر از رفتار مرجع باید mode صریح و آزمون مستقل داشته باشد. دامنه‌های معتبر 512 تریالی باید جدا از مورد تاریخی آزمایش شوند؛ طول دنباله به‌تنهایی تعریف دامنه اعتبار نیست.

### R3 — تطابق استنباط روی داده‌های واقعی شکست M18

وضعیت: BLOCKED_BY_R2؛ ابتدا یک مورد شکست، سپس کل شبکه تاریخی.

- همان `u/y`، truth، config، free/fixed indices، prior و startpointها را به دو تولباکس بده.
- ابتدا objective را در truth، prior start و هر دو endpoint ارزیابی کن؛ سپس MAP، termination، Hessian، Sigma/Corr، LME، AIC/BIC و انتخاب restart را مقایسه کن.
- در مرحله تشخیص از truth-start/oracle استفاده کن؛ آن را جای شروع واقعی آزمون بازیابی قرار نده.
- برای پارامترهای ضعیفاً قابل‌شناسایی، اختلاف theta به‌تنهایی معیار رد/قبول نیست؛ objective، trajectory، curvature و نتیجه انتخاب مدل نیز لازم‌اند. اختلاف unexplained باید باز بماند.
- برای هر سلول MATLAB و Python خطای بازیابی را جداگانه و به‌صورت paired گزارش کن. شکست‌ها در مخرج باقی بمانند.

خروج: پاسخ مستند به اینکه ضعف بازیابی ناشی از پورت است یا در مرجع نیز رخ می‌دهد. اگر MATLAB بهتر است، اولین اختلاف پیدا و اصلاح شود. اگر هر دو برابر و ضعیف‌اند، M18 تاریخی همچنان FAIL است و محدودیت آزمایش ثبت می‌شود.

### R4 — آزمایش مستقل بازیابی و شناسایی‌پذیری

وضعیت: BLOCKED_BY_R3؛ معیارهای این پروتکل هنوز تعیین و freeze نشده‌اند.

- طرح stable/volatile، شمار تریال‌های معتبر، دامنه truth، تعداد replicate، start/restart و معیار انتخاب مدل را پیش از اجرای تأییدی ثبت کن.
- تعیین حجم نمونه و معیارهای عددی در pilot مستقل انجام و سپس protocol hash و seedهای holdout ثابت شود؛ خروجی pilot شاهد تأییدی نیست.
- بازیابی joint ادراکی+مشاهده‌ای، oracle و conditional slice جدا گزارش شوند. slice با سایر پارامترهای ثابت اثبات joint identifiability نیست؛ برای joint از profile با بازبرازش nuisanceها و بررسی curvature/تداخل استفاده شود.
- bias، RMSE با تعریف مخرج روشن، correlation، uncertainty، convergence و model confusion به تفکیک model/parameter/regime گزارش شوند؛ معیار تجمیعی نباید شکست یک پارامتر را پنهان کند.
- هر دو تولباکس روی داده مشترک اجرا شوند؛ همان protocol از پیش ثابت در حالت شکست هم حفظ شود.

خروج: پروتکل نسخه‌دار جدید و نتیجه مستقل. تغییر طراحی آزمایش یا معیارها به معنی PASS شدن مجدد M18 قدیمی نیست. ادعای recovery فقط به رژیم‌های تأییدشده محدود باشد.

### R5 — گسترش شواهد پوشش و تأیید CPU/GPU

وضعیت: BLOCKED_BY_R3؛ تأیید workload جدید بازیابی وابسته به R4 هم هست.

- برای همه خانواده‌های علمی موجود در Migration Matrix، ماتریس family × response معتبر × config × regime × backend بساز؛ ترکیب نامعتبر با علت مشخص شود.
- گیت‌های M12 پوشش پیاده‌سازی‌اند؛ برای ادعای fitting همه خانواده‌ها، fixtureهای end-to-end و edge case متناظر نیاز است. شکاف‌ها با همان Matrix ID باز شوند.
- پس از هر اصلاح عددی، goldenهای مسیر وابسته و regression CPU x64 اجرا شوند؛ قبل از ادعای GPU جدید، همان workload روی H100 واقعی آزموده شود.
- forward/objective/fit/statistics، batch-single، padding/mask و restart selection مقایسه شوند. شواهد تاریخی M14–M17 حفظ شوند ولی به کد جدید تعمیم خودکار داده نشوند.
- شرایط اشتراکی H100 ثبت شود؛ خالی‌شدن کامل سرور شرط اجرا نیست. correctness و throughput جدا گزارش شوند.

خروج: هر ادعای backend/family به artifact مشخص متصل باشد؛ skip جای شواهد فیزیکی را نمی‌گیرد.

### R6 — انتشار تولباکس و سپس بسته مقاله

وضعیت: BLOCKED_BY_R0–R5 و معیارهای موجود release.

- نصب تمیز و مثال‌های fit/sim/sample بدون MATLAB، API سفارشی، مستندات مهاجرت، محدودیت‌ها و provenance تکمیل شوند.
- M19 داده و خروجی نسخه‌دار را freeze کند؛ مقاله از همان خروجی‌ها ساخته شود.
- M20 تنها با تکمیل `ACCEPTANCE_CRITERIA.md` بسته شود. اگر M18 تاریخی به علت محدودیت مشترک همچنان FAIL است، معیار علمی release باید در تصمیم صریح و قابل‌بررسی با شواهد R3/R4 نسخه‌بندی شود؛ این پلن چنین استثنایی را اعطا نمی‌کند.
